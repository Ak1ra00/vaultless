why this is safe

The oracle's private scalar k never leaves the device, and it only ever sees a blinded, random-looking curve point — never your passphrase or the final password. Nothing is stored on this device or in the cloud; the same passphrase and index always regenerate the same password.

how it works & why it's safe

vaultless is a deterministic password manager: instead of storing a vault of secrets anywhere, every password is re-derived on demand from two things — your master passphrase and a sub-index (pick a different number per account). Same two inputs, same password, every time. Nothing to sync, back up, or leak.

The catch with pure deterministic derivation is that anyone who steals your master passphrase can recompute every password you've ever generated offline. vaultless closes that gap with a second factor that never leaves a physical device: a two-party oblivious PRF (OPRF) over ristretto255.

  1. Your browser hashes passphrase‖index to a curve point P, then blinds it with a random scalar r to get B = r·P — indistinguishable from a random point.
  2. B is sent to the oracle (hardware over WebSerial, or the in-browser simulator).
  3. The oracle multiplies by its private scalar k and returns B′ = k·B.
  4. The browser unblinds: S = r⁻¹·B′ = k·P, then expands S through HKDF-SHA256 into the final password.
why this resists theft
  • The oracle only ever sees a blinded point — never your passphrase or index in a form it can use to precompute anything.
  • Without the oracle's private scalar k, a stolen passphrase alone cannot regenerate any password.
  • Without the passphrase, a stolen or cloned oracle alone cannot regenerate any password either — both factors are required.
  • Derivation requires the oracle to be physically connected — but note it auto-approves every request it receives, so anything with access to the serial port can use it while it's plugged in.
  • Nothing is persisted: not the passphrase, not intermediate points, not the resulting password.

flashing

Easiest: plug the board in over USB and use the Flash LilyGO firmware button above — it uses ESP Web Tools over WebSerial, no local toolchain needed.

To build from source instead:

git clone https://github.com/Ak1ra00/SK
cd SK/firmware
pio run -e esp32dev -t upload

The private oracle scalar k is generated on first boot from the hardware RNG and stored in NVS — it never touches the serial line, the browser, or this repo. Firmware source: firmware/src/main.cpp.
